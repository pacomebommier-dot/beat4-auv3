# BEAT 0.5.13 build13 — authoritative 16/32-step active-cycle rules
Supersedes all destination-owned queue rules in unbuilt 0.5.12; archived under docs/OLD.
In 4/4, 16 sixteenth steps = one host bar, 32 = two host bars.
The ACTIVE project's saved steps determine the next queued change. No saved value defaults16.
The incoming project's steps only matter after it becomes active. No zero-queue or 4-bar mode.
The selector has exactly16/32; SAVE stores its value on ACTIVE, never pending destination.
New explicit steps field; never reinterpret legacy pcMode0/1/2 or beat queue as steps32.
Titles/BPM/sub notes/legacy metadata persist unchanged. Only explicit steps32 opts into32.
16: strict next AUM bar. 32: strict next end of the active project's two-bar cycle.
Cycle origin: project activation; on fresh PLAY/recovery use current AUM bar as estimated origin.
A scheduled activation preserves its scheduled boundary as origin even if observed one buffer late.
Same-PC confirmation preserves origin and any tempo ramp. Backward seek reanchors to AUM bar.
No deadlock on queued incoming PC64..127 or missing/recovered host timeline.
Incoming PC0..63 confirms actual hardware activation immediately, never echoes it.
AUM scheduling remains estimated until hardware confirmation; no claim of observing Drum1 phase.
Tempo ramp starts upon selection from actual host BPM toward incoming saved BPM.
<=10BPM difference: one host bar; >10: two host bars; may continue after activation.
STOP clears pending/ramp, STOP selection recalls BPM immediately. Latest request wins;
selecting ACTIVE cancels pending/ramp; failed local MIDI output stays blocked until new user request.
Keep transport/MIDI encodings, audio and UI layout except two selector values and queue text/menu.
Deliver raw unsigned IPA in dedicated BEAT/0.5.13/IPA; documents in DOCUMENTS, obsolete docs in OLD.
Native build/public push requires explicit authorization following prior auto-review rejection.
